这个项目用于把飞书群自定义机器人收到的告警消息，按 客服账号 自动原话转发给对应客服。

正式流程不需要手动收集或填写客服的 open_id。客服接收人由飞书多维表格里的“人员”字段决定，程序会定时把多维表格同步成本地 rules.json，再按 rules.json 转发消息。

公开仓库不会提交真实 .env、.state/、rules.json，避免泄露飞书密钥、群 ID、人员 open_id 和消息状态。

本次更新亮点：Windows Server 自动部署

现在可以把 Codex 和开发工作留在 Mac，本地测试通过后把代码推到 GitHub 或 Gitee；Windows Server 不需要开放公网 SSH，由任务计划程序主动拉取生产分支并自动更新服务。

  • Windows Server 使用 SYSTEM 后台任务常驻运行规则同步和消息轮询，不需要保留 CMD/PowerShell 窗口。
  • 自动部署任务每 1 分钟检查远程 main 是否有新 commit，没有变化只记录 No remote changes detected.。
  • 有新版本时先在 staging 目录执行 npm ci 和 npm test，通过后才停止正式任务并切换代码。
  • 部署失败不会替换正式目录，也不会中断当前正在运行的服务，错误写入 logs/deploy.log。
  • 运行配置和状态仍只保存在 Windows 本地：.env、.state/、rules.json、logs/ 不进入 GitHub。

详细服务器部署见 docs/WINDOWS_SERVER_DEPLOY.md。

一、整体链路

外部系统
  -> 飞书群自定义机器人 webhook
  -> 目标飞书群出现告警消息
  -> poll 进程每 5 秒读取目标群消息
  -> 解析消息里的客服账号
  -> 从 rules.json 找到对应接收人
  -> 自建应用机器人把原文私聊发送给对应客服
  -> 写入 .state/send-records.jsonl 发送记录
  -> 给配置的管理员发送一条简短处理回执

同时还有一个规则同步进程：

飞书多维表格
  -> sync-rules 进程每 60 秒读取规则
  -> 生成/覆盖 rules.json
  -> poll 进程下一轮自动使用新规则

二、日常使用方式

1. 修改客服分发规则

日常只改飞书多维表格，不要手动改 rules.json。

多维表格字段如下：

字段名 类型 作用
客服名称 文本 告警消息里 客服账号： 后面的名字，需要完全一致
接收人 人员 选择要收到提醒的飞书人员，可选一个或多个人
是否启用 复选框/单选/文本 为空默认启用；关闭后该行不会同步

示例：

客服名称：静静
接收人：张三
是否启用：是

如果告警消息里出现：

客服账号：静静

程序会识别 静静，然后把原始告警消息发送给多维表格中 静静 对应的接收人。

2. 启动程序

在 Windows 电脑上，日常只需要双击：

windows-start-all.bat

它会打开两个窗口：

Feishu rules sync
Feishu message poll

两个窗口都要保持打开。

  • Feishu rules sync：每 60 秒同步一次多维表格规则。
  • Feishu message poll：每 5 秒读取一次目标群消息，并自动分发。

如果关闭窗口、电脑睡眠、断网，自动分发就会停止。

3. 发送内容

现在发送给客服的是群里机器人消息原文，不再额外套话术模板。

也就是说，群里机器人发什么内容，程序就把同一段文字原样私聊给对应客服。日常只需要维护多维表格里的客服对应关系。

4. 管理员回执

管理员 open_id 从 .env 的 ADMIN_NOTIFY_OPEN_ID 读取，不再从 rules.json 读取，也不会提交到公开仓库。

之后即使 sync-rules 更新了 rules.json，管理员也不会变化。要更换管理员，只需要修改 .env 里的 ADMIN_NOTIFY_NAME 和 ADMIN_NOTIFY_OPEN_ID，然后重启 Feishu message poll 窗口或 Windows 计划任务。

管理员会收到成功和失败的简短私聊回执。失败回执会说明问题定位和下一步；管理员回执自身发送失败只会在 poll 窗口记录 admin_notification_failed，不会改变原客服转发结果。日志只显示管理员脱敏 ID，不显示完整 open_id。

5. 查看发送记录

程序每次尝试给客服发私聊，都会写一条本地记录：

.state/send-records.jsonl

查看最近 20 条：

npm run send-log

查看最近 50 条：

npm run send-log -- --limit=50

重点看这几列：

列 含义
状态 success 表示飞书接口返回发送成功；failed 表示发送失败
客服 从告警消息里解析出来的客服账号
接收人 多维表格人员字段里的接收人名称
receive_id 实际发送到的飞书人员 open_id
发出消息 飞书返回的私聊消息 ID
错误 失败原因

这版反馈先使用飞书发送接口的返回结果判断成功或失败，不依赖事件回调。事件回调后续更适合继续做“客服是否回复、是否点确认”这类闭环。

6. 停止程序

直接关闭两个工作窗口即可：

Feishu rules sync
Feishu message poll

关闭后不会继续同步规则，也不会继续转发新消息。

7. 修改规则多久生效

默认最多 60 秒生效。

原因是 sync-rules 默认每 60 秒读取一次多维表格，并覆盖 rules.json。下一轮 poll 读取消息时，就会使用新的 rules.json。

如果想更快，可以在 .env 里调小：

RULES_SYNC_INTERVAL_MS=30000

表示每 30 秒同步一次。

8. 电脑是否必须一直开机

是的。

目前这套程序运行在公司 Windows 电脑上，所以这台电脑需要：

保持开机
不自动睡眠
网络常连
两个工作窗口保持打开

如果公司后续想彻底不用本地电脑运行，需要把这套程序部署到服务器或云主机。

三、首次部署到 Windows

1. 安装 Node.js

在 Windows 电脑安装 Node.js LTS：

https://nodejs.org/

安装后打开 CMD，确认：

node -v
npm -v

2. 复制项目文件

把整个项目文件夹复制到 Windows，例如：

C:\feishu-alert-forwarder

不要只复制 src，要复制整个文件夹。

3. 安装依赖

在项目文件夹里打开 CMD：

cd /d C:\feishu-alert-forwarder
npm install

4. 填写 .env

复制 .env.example 为 .env，然后填写真实值。

必须填写：

FEISHU_APP_ID
FEISHU_APP_SECRET
TARGET_CHAT_ID
SOURCE_APP_ID
RULES_BASE_APP_TOKEN
RULES_BASE_TABLE_ID

可选填写：

FEISHU_DOMAIN
POLL_INTERVAL_MS
POLL_PAGE_SIZE
RULES_FILE
SEND_RECORDS_FILE
PROCESS_EXISTING_MESSAGES
ADMIN_NOTIFY_ENABLED
ADMIN_NOTIFY_NAME
ADMIN_NOTIFY_OPEN_ID
RULES_BASE_VIEW_ID
RULES_SYNC_INTERVAL_MS
RULES_FIELD_SERVICE_NAME
RULES_FIELD_RECEIVER
RULES_FIELD_ENABLED

客服接收人不需要手动填写个人 open_id；管理员回执如果要启用，需要在 .env 填写 ADMIN_NOTIFY_OPEN_ID。

四、环境变量说明

变量名 是否必填 作用
FEISHU_APP_ID 必填 自建应用的 App ID
FEISHU_APP_SECRET 必填 自建应用的 App Secret
FEISHU_DOMAIN 可选 飞书开放平台域名，国内默认 open.feishu.cn

SOURCE_APP_ID 必填 群自定义机器人的 app_id，用于只识别它发出的消息
POLL_INTERVAL_MS 可选 轮询群消息间隔，默认 5000 毫秒
POLL_PAGE_SIZE 可选 每次读取最近多少条群消息，默认 20
RULES_FILE 可选 规则缓存文件，默认 rules.json
SEND_RECORDS_FILE 可选 发送记录文件，默认 .state/send-records.jsonl
PROCESS_EXISTING_MESSAGES 可选 首次启动是否处理历史消息，默认 false
ADMIN_NOTIFY_ENABLED 可选 是否给配置的管理员发送处理回执，默认 true
ADMIN_NOTIFY_NAME 可选 管理员回执接收人显示名，默认 管理员

RULES_BASE_VIEW_ID 可选 指定只同步某个视图
RULES_SYNC_INTERVAL_MS 可选 同步多维表格间隔，默认 60000 毫秒
RULES_FIELD_SERVICE_NAME 可选 多维表格里的客服名称字段名
RULES_FIELD_RECEIVER 可选 多维表格里的接收人字段名
RULES_FIELD_ENABLED 可选 多维表格里的是否启用字段名

七、排查问题

提示 Missing required env

说明 .env 缺少对应变量。

例如：

Missing required env: TARGET_CHAT_ID

就去 .env 里填写：

TARGET_CHAT_ID=oc_xxxxxxxxx

修改多维表格后没有生效

先看 Feishu rules sync 窗口是否还开着。

再确认：

RULES_BASE_APP_TOKEN
RULES_BASE_TABLE_ID
RULES_FIELD_SERVICE_NAME
RULES_FIELD_RECEIVER
RULES_FIELD_ENABLED

是否和多维表格实际字段一致。

群里有消息但没有转发

检查：

TARGET_CHAT_ID
SOURCE_APP_ID
rules.json

常见原因：

  • TARGET_CHAT_ID 不是当前群。
  • SOURCE_APP_ID 不是群自定义机器人的 app_id。
  • 多维表格里的客服名称和告警消息里 客服账号： 后面的名字不完全一致。
  • Feishu message poll 窗口已经关闭。

重复发送

正常情况下不会重复发送，因为 .state/poll-state.json 会记录已处理消息。

如果删除 .state/poll-state.json，程序会重新建立基线。默认 PROCESS_EXISTING_MESSAGES=false 时，首次启动不会处理历史消息，只处理之后新出现的消息。

想看发给谁了、有没有成功

运行：

npm run send-log

如果看到 success，表示飞书接口已经返回发送成功。如果看到 failed，看最后的错误列，通常是接收人权限、open_id、应用权限或飞书接口错误。

.env
