把一个项目的源码变成一部可以继续生长的本地项目书。

这不是“把文件树丢给聊天机器人”。源码是事实底座；项目是后台空间，主书是用户进入项目后的界面。读者先进入一部连续讲解主书，在书里做划词旁注，也可以在书底另开一次探索。只有用户明确确认后，一次探索的回答才会长成一本可回看的探索小书。

本地项目源码
  └─ 项目空间（后台数据与上下文）
      └─ 主书（用户进入项目后的界面）
          ├─ 划词旁注
          └─ 书底探索 ─ 确认 ─ 探索小书

在线演示

https://dontttbefly-sketch.github.io/vibe-shelf/

GitHub Pages 上是纯静态演示：首页、开书动效、上传页（放进项目、写侧重点、右页目录实时更新）和内置的 PUPKIT 示例书都可以试，阅读时的旁注存在浏览器本地。生成项目书和 AI 回答需要服务端，请按下面的「快速开始」在本地运行。

现在可以做什么

  • 首页点「把我的项目变成书」，右侧那本书会飞到书桌中央并翻开：左页写，右页看进度。
    • 左页：一个输入框——放进项目（选或拖入本地文件夹，或填公开 GitHub 仓库），再用一两句话写下你最想读懂的侧重点（可不填，不填就先讲清全貌），然后生成。项目名自动取文件夹名或仓库名。
    • 右页：这本书的扉页，书名和你写的侧重点实时排成标题与副标题；下面的目录「放进项目 / 写下侧重点 / 写成主书」只在真的发生后才打勾，生成时显示真实阶段。
  • 侧重点会原话交给模型：第一章交代全貌，其余篇幅优先给你关心的源码、调用链与机制；材料里找不到的内容会如实写明，不编造。
  • 每个导入项目都会保存一份不可变的源码快照；之后的解释、旁注和探索都只从该项目的源码里取上下文。
  • 首页里的项目小书会直接打开主书；project.html 只作为旧链接兼容跳转，不再承担项目内页。
  • 阅读器不改原书正文：划词旁注仍是叠加层；书底的“继续探索”则是独立、可追问的项目级会话。
  • public/notes.js / public/notes.css 是唯一维护的阅读器主线：它已经吸收旧单页版里成熟的划词、晋升恢复、全局问答和插卡动效能力。
  • 回答默认只是会话记录；按“让这个问题长成一本书”才会生成子书。子书也能继续做旁注和探索。
  • 内置 PUPKIT 前端代码解剖课，原有旁注会保留并自动迁入项目空间。

导入支持本地文件夹和公开 GitHub 仓库（owner/name 或仓库地址）。云同步、后台监听和思维导图画布还不在当前范围内。

快速开始

要求：Node.js 18+。如果需要 AI 回答，再配置任意 OpenAI 兼容接口的 API Key（OpenAI / DeepSeek / MiniMax / Kimi / 本地 Ollama 都可以）。

git clone https://github.com/dontttbefly-sketch/vibe-shelf.git
cd vibe-shelf
cp .env.example .env        # 需要 AI 时填写接口地址 / Key / 模型名
node scripts/migrate-pupkit.mjs
node server.mjs             # 打开 http://localhost:8899

macOS 上也可以双击 启动知识书架.command。它会先安全地执行一次 PUPKIT 迁移，再启动服务。

没有配置模型时，阅读、旁注的本地保存、项目浏览仍可用；涉及 AI 生成的入口会明确提示模型服务尚不可用。

使用路径

  1. 打开首页，点「把我的项目变成书」。放进项目文件夹（或填 GitHub 仓库），写下侧重点，点「生成项目书」。
  2. 服务端保存源码快照，并后台生成项目主书；右页目录显示当前阶段，期间可以先去逛书架。
  3. 生成完成后直接进入主书。主书承担“整个项目是怎么回事”的叙事主干。
  4. 阅读时划词可做旁注；想问书外的细节，就到书底开始“继续探索”。
  5. 在探索会话中继续追问。若这条路径值得单独保存，点击“让这个问题长成一本书”；它就成为这本项目书架下的一本探索小书。

├── lib/                         项目快照、检索、书、探索、HTTP 服务
├── public/

│   ├── upload-motion.js         首页 → 上传页的「翻开这本书」转场
│   ├── upload-workspace.css     书桌上的对开书：书写页与扉页
│   ├── static-demo.json         GitHub Pages 静态演示用的示例书快照
│   ├── project.html             旧项目页地址的兼容跳转壳
│   ├── notes.js / notes.css     叠加式旁注阅读层
│   └── explore.js / explore.css 项目探索会话界面
├── data/projects/<项目 id>/
│   ├── source/<快照 id>/        不可变源码快照
│   ├── books/<书 id>/           书元数据与原始 HTML
│   ├── notes/<书 id>.json       这本书的旁注

运行时新导入的项目数据和编译产物默认不会提交到 Git；仓库只保留 PUPKIT 作为可立即打开的示例。

推送到 main 后，.github/workflows/pages.yml 会先跑 npm test，通过后把 public/ 发布到 GitHub Pages。

模型配置（.env）

变量 说明
SHELF_API_URL 完整的 chat/completions 端点
SHELF_API_KEY API Key，仅存在本地服务端
SHELF_MODEL 模型名
PORT 服务端口，默认 8899
SHELF_REASONING_SPLIT 是否发送 MiniMax 专有的 reasoning_split 参数。不填则按端点域名自动判断（含 minimax 才发），走代理时用 1 / 0 强制开关
SHELF_PROMPT_BUDGET_BYTES 可选。生成主书时喂给模型的源码总量上限，默认 2.5MB（对应 1M token 上下文）。换成 128K 上下文的小模型必须调小（约 300000），否则请求会因超长被上游拒绝
GITHUB_TOKEN 可选。GitHub 导入的树查询用它提高限额（文件正文走 raw 端点，不占限额）

设计原则

  1. 源码是事实，主书是主干：AI 从项目快照中取证，但读者从一份连贯的项目讲解开始。
  2. 项目退到后台，书成为界面：用户从书架直接进入主书，返回书架固定在顶部右侧，作为低存在感辅助动作。
  3. 书内旁注与书外探索分开：旁注解释当前文本；探索开辟一个新的问题方向。
  4. AI 不越过用户：回答不会自动变书，只有明确确认的探索才沉淀为小书。
  5. 不改写原书：旁注、探索和导航都以叠加或外层页面实现，原书正文保持不动。
  6. 本地优先、快照可追溯：每一本书和每次探索都知道自己依赖的是哪一版源码。
